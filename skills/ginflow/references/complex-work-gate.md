# Complex-work gate

Use this gate before implementation whenever **any** trigger below applies:

- The request needs brainstorming to clarify intent, requirements, or design.
- The work needs a written spec or implementation plan.
- Implementation takes more than two meaningful steps.
- The work can be divided into more than two independently understandable problems or deliverables.

## Before implementation

1. Shape the work before changing implementation files. Clarify material ambiguity with the user. Brainstorm when the design is not settled; create a spec and/or plan when needed to make the behavior, scope, and execution order clear. Do not create documents that add no useful clarity.
2. Break multi-problem work into appropriately scoped cards. Each card must have an objective, bounded scope, observable acceptance criteria, and links to relevant artifacts. Record dependencies when one card depends on another. Follow the card shape and creation guidance in the Ginflow skill.
3. Make the required card or cards available in Kanban. Implementation begins only after a card is selected and its required fields are present. Work only within that selected card's scope; select subsequent cards according to the project's dependency and dispatch workflow.

For a request with none of these triggers, use the lightweight path unless project rules require otherwise. If a trigger emerges during implementation, pause implementation, shape the remaining work, and establish the required card scope before continuing.

## Ready to implement

The gate is satisfied when the work is sufficiently clarified, required specs/plans exist, and a selected card has a clear objective, scope, acceptance criteria, workspace, status, assignee, and links. Continue with the Ginflow execution startup and completion requirements.
